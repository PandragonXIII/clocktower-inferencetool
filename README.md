# 血染钟楼推理助手（BOTC Reasoning Assistant）

## 1. 项目简介

本项目旨在开发一个基于**符号推理（Symbolic Reasoning）**的《血染钟楼》（Blood on the Clocktower）辅助工具。

用户输入自己已知的游戏信息，包括身份、技能行动及结果、玩家死亡情况，以及其他玩家的身份声明等。系统根据游戏规则进行逻辑推理，判断信息是否矛盾，排除不可能的身份，并帮助用户分析其他玩家的身份与阵营。

**核心目标：通过严格的规则推理，而非 LLM 猜测，提供可靠、可解释的推理结果。**

## 2. 核心技术思路

采用 **规则建模 + 约束求解引擎 + 结果解释** 的架构。

1. **规则建模**：人工将游戏规则转化为逻辑约束，包括角色配置、技能效果、状态变化、中毒与醉酒等机制。
2. **信息输入**：将用户已知的事件、技能结果及可选假设转化为约束条件。
3. **约束求解**：使用现成推理引擎（优先考虑 Z3 SMT Solver，也可评估 Clingo / 现有 BOTC 求解器），判断是否存在满足全部约束的合法游戏状态。
4. **结果分析**：通过增加额外约束，判断玩家身份是否可能、必然或不可能，并提取矛盾信息。
5. **结果呈现**：将求解结果转化为直观的身份候选、矛盾提示及推理解释。

```text
游戏规则 ──→ 人工建模 ──→ 逻辑约束 ──┐
                                     ├──→ SAT/SMT 求解器
玩家信息 ──→ 结构化输入 ──→ 观测约束 ──┘          │
                                                ↓
                                      推理结果分析
                                                │
                                                ↓
                              身份排除 / 矛盾检测 / 推理解释
```

不直接暴力枚举所有可能的游戏状态，而是利用成熟求解器完成约束传播与搜索。

## 3. 功能规划

### P0 — MVP（必须实现）

- **游戏状态管理**：创建对局、玩家座位、昼夜时间轴、死亡记录。
- **信息录入**：记录身份声明、技能行动及结果、公开事件，区分确定信息与可撤销假设。
- **规则推理内核**：实现《暗流涌动》的基础角色配置、部分核心技能和状态约束。
- **一致性检测**：判断已有信息是否存在逻辑矛盾。
- **身份推理**：查询玩家可能、必然或不可能具有的身份与阵营。
- **交互式推理**：添加、修改或撤销假设，重新计算并展示结果。

### P1 — 重要扩展

- **可解释推理**：定位矛盾信息，展示身份排除依据。
- **规则完善**：支持完整角色技能、多夜状态、中毒、醉酒及角色变化。
- **可视化交互**：圆桌布局、身份候选高亮、历史记录、存档、示例残局。
- **信息价值分析**：比较不同假设，提示值得进一步验证的信息。

### P2 — 后续功能

- **概率推理**：可能世界计数、基于概率模型的身份预测。
- **行动建议**：技能目标选择、处决建议、反事实推演。
- **智能交互**：使用 LLM 生成自然语言推理解释。

## 4. 开发原则

- **规则正确性优先**：推理结论必须符合已实现的游戏规则。
- **求解器负责判断**：LLM 不参与最终逻辑裁决。
- **控制问题规模**：优先支持《暗流涌动》，逐步完善复杂机制。
- **交互性能优先**：争取常规推理秒级完成，避免完整状态空间枚举。
- **结果可解释**：不仅给出身份判断，还应尽可能说明依据与冲突来源。

## 5. 预期成果

实现一个可交互的血染钟楼辅助推理系统，形成以下使用闭环：

**录入游戏信息 → 自动检测矛盾 → 排除不可能身份 → 调整假设 → 实时更新推理结果。**
